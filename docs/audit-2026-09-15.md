# Repfind audit — 2026-09-15

## Scope

Source, production hosting, product data, search relevance, desktop/mobile flows, accessibility, privacy, dependency security, and deployment hygiene.

## Production map

- Repository: `jack108510/RepFind`
- Production branch: `main`
- Hosting: GitHub Pages with custom domain `repfind.ca`
- Deployment: `.github/workflows/deploy.yml`
- Application: static HTML/CSS/JavaScript; Supabase authentication and haul sync; optional n8n search interpretation; Capacitor iOS shell points to the production URL.

## Confirmed findings and remediation

| Severity | Finding | Remediation |
|---|---|---|
| High | The 70,463-row catalog contained 46,728 duplicate `(platform, itemID)` rows. Duplicate IDs were mutated in the browser, breaking direct marketplace links and competing in rankings. | Catalog is now 23,735 unique listings. IDs remain unchanged. Added deterministic importer deduplication and a deployment-blocking validator. |
| High | Anonymous Supabase clients could read analytics tables, including search-query records. | Browser analytics and persistent analytics identifiers are disabled and cleared. Added a Supabase migration that removes public read/update/delete access while retaining insert-only policies for any future re-enable. The migration must be applied before analytics can be re-enabled. |
| High | Dependency audit reported high-severity advisories in transitive `@xmldom/xmldom` and `brace-expansion`. | Lockfile updated; `npm audit` now reports zero vulnerabilities. |
| Medium | Two-word searches accepted one token and silently broadened to misleading results. | Multiword search now requires meaningful-token agreement. Nonsense combinations return an honest empty state. Phrase synonyms and category aliases are explicit. |
| Medium | Four-letter fuzzy matching made `sofa` match `soft`; home searches surfaced apparel. | Four-letter fuzzy matching disabled, home-category aliases added, and apparel false positives excluded for sofa/furniture intent. |
| Medium | Suggested `designer bags` search ranked generic products ahead of designer brands. | Treated “designer” as a modifier while boosting recognized luxury brands. |
| Medium | Pages deployment uploaded the entire repository. | Workflow now validates data and publishes only six runtime assets. |
| Medium | Browser storage parsing, search fallback rendering, and auth network failures could throw uncaught exceptions. | Added safe storage decoding and guarded error handling. |
| Medium | Hidden dialogs remained exposed to accessibility tools; cross-sell cards and utility controls lacked complete keyboard/labels support. | Added dialog `aria-hidden` state, keyboard card activation, visible focus, reduced-motion behavior, status announcements, and descriptive removal/agent controls. |
| Low | USD prices changed between cards and haul totals due to premature CNY rounding. | Preserved price precision until display formatting. |
| Low | Privacy policy omitted search automation, Supabase/account data, local storage, retention, and data-request details. | Replaced with service-specific disclosure and linked it from the application. |

## Verification

- Product validator: 23,735 unique listings; zero duplicate or malformed keys; all marketplace IDs numeric.
- Catalog payload: 13,238,245 bytes → 4,406,855 bytes.
- Inline JavaScript: syntax valid.
- Python importer/validator: bytecode compilation passed.
- Workflow YAML: valid.
- npm audit: zero known vulnerabilities.
- Mobile regression at 390×844: no horizontal overflow; 24 Jordan 4 cards rendered; first detail panel opened; exact `$36.92` price persisted; haul add/open/remove labeling worked.
- Search regression: relevant Jordan 4, AirPods, designer-bag, and sofa results; `galaxy watch` and `nike nonsense` returned no misleading inventory.
- Browser regression: zero JavaScript exceptions and zero console errors.
- Privacy regression: no analytics REST writes and no `rf_sid`, `rf_vid`, or `rf_utm` identifiers created while analytics is disabled.
